# Graveyard UI visual check, 2026-11-13 (Claude)

Defects found by Claude's real-browser visual check on 2026-11-13 (Chrome at 1352x761 desktop, headless Chromium at 375x812, demo parse-server, package ldapjs). Behavior and data are correct (calibration row sums 72 + 3 = 75, no horizontal scroll at 375px, no console errors); these are presentation bugs only.

D1. Desktop layout: the home page and the graveyard page have no side gutter and no max width. Text, headings and demo cards touch the left edge of the viewport at 1352px. Expected: a centered content column (max width around 1200px) with at least 16px side gutter on phones and comfortable gutter on desktop.
D2. Summary counts: the Dead/Dying/Ailing/Alive count chips are rendered inside a list whose default list bullets are visible as stray dots to the left of each chip (desktop and mobile). Expected: no bullets; chips in a tidy row (wrapping on phones).
D3. Tombstone card: the grade is printed twice (an outlined "DEAD" badge above the package name and a "DEAD" label under the score). Expected: one grade label. Also the arched outline of the stone is clipped at the very top, and a horizontal rule line crosses inside the arch below its top. Expected: the full arch outline visible, no stray horizontal line.
D4. Breakdown table at desktop widths: the Status, Points/weight and Source columns are so narrow that single words break mid-word: "Status" -> "Statu/s", "Known" -> "Know/n", "Calibration" -> "Calibr/ation", "registry.npmjs.org" -> "registry.np/mjs.org". Expected: short status/points cells never break inside a word; hostnames break only at dots if at all; the signal-description column takes the remaining width.
D5. Calibration row Source cell says "No source recorded". Expected: it names its origin, e.g. "Engine rule: declared_abandoned", because calibration is computed by the death-score engine, not fetched.
D6. Mobile (stacked table, 375px): the table footer Total row renders as several empty full-width bordered bars before "Total: 75 / 100". Expected: one clean Total line.
D7. Page heading focus: after navigation the page h1 (home "Last Rites" and graveyard "The Graveyard: ...") shows a visible blue focus box on load, because focus is moved to it programmatically. Expected: keep the programmatic focus for screen readers but show no outline for programmatic (non-keyboard) focus; keyboard focus rings elsewhere stay visible.
